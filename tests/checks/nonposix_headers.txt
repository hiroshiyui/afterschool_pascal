# What the runtime asks of a target that is not POSIX, measured against
# mingw-w64 (ADR-0369).
#
# **The answers here are a toolchain's as well as this source's, and that was
# learned the hard way.** `runtime-nonposix` runs wherever a mingw-w64 cross
# compiler is installed, and for one commit that included the container matrix
# job -- where Ubuntu 24.04's mingw-w64 reported `runtime/pasrt.c` as
# *compiling* while Debian trixie's and this developer's (GCC 14-win32 and
# 16-win32) report it blocked on `_longjmp`. One row cannot be true of both.
#
# So the toolchain is pinned the way ADR-0189 pins a Unicode version: an
# oracle that changes under you is not one. The `non-posix` CI job is the only
# place mingw-w64 is installed, it is a single Debian image, and it is where
# NONPOSIX_REQUIRE is set. A checkout with a different mingw-w64 may
# legitimately disagree with a row below, and what that means is that the
# blocker is that toolchain's and not this runtime's -- doc/roadmap.md's
# Windows row is where such a difference gets written down.
#
# `runtime-isoc` bounds each translation unit by the headers it may include;
# this asks the question that one cannot: **are those headers there on a
# platform that is not POSIX**, and does the unit compile once they are. Every
# target this tree compiles the runtime for is `*-linux-gnu` -- `target-sizes`
# builds it for nine triples and all nine are Linux -- so until this file the
# answer was a measurement somebody took by hand once and wrote into
# doc/roadmap.md.
#
# **The whole point is that a floor becomes a list.** A missing header is a
# *fatal* error, so compiling the unit tells you the first one and nothing
# about the rest: doc/roadmap.md's Windows row said `pasrt_posix.c` stops at
# `netdb.h` and that "the rest of its 1 177 lines was never reached". Each
# `#include <...>` is therefore probed on its own, one one-line translation
# unit per header, and what comes back is every header the target lacks.
#
# Two claims, both directions each:
#
#   unit:    <name>  compiles | blocked | crt <MACRO>
#   header:  <name>  <header>        one row per header the target lacks
#
# **`crt` is a third answer because two were hiding one.** A unit that does not
# compile as the toolchain is configured, and does compile once the target's
# modern C runtime is selected, wants no change to this source at all -- it is
# not in the position of one that names a header nobody has. It is checked in
# *both* directions: the unit must fail without the macro and compile with it,
# so the row cannot become a way to excuse a unit that is simply broken.
#
# A unit that stops compiling, one that starts, a header that goes missing and
# a header that arrives are four failures and not one -- the KNOWN_GAP rule
# (ADR-0013) applied to a port. Progress must be recorded here, so closing a
# blocker is a commit that edits this file.
#
# What this cannot see is a unit blocked for a *new* reason while still
# blocked for an old one: the status is one bit. doc/sop.md 7 carries that.

# --- which translation units compile for the target -----------------------
#
# pasrt_unicode.c compiling clean is the whole of AP 6.4.15 -- normalisation
# and grapheme segmentation over tables, and nothing else. It is the one unit
# a port gets for free, and it is measured here rather than hoped for.
#
# **pasrt.c compiled here for one week and no longer does, and that is a
# decision rather than a regression** (ADR-0380). It reaches the non-local
# goto's jump through `_longjmp`, which POSIX declares and mingw-w64 does not;
# ADR-0373 bought this row with the runtime's only preprocessor conditional,
# and dropping Windows as a target bought the conditional back. The row is
# `blocked` because that is what is true, and the gate prints the first lines
# of the diagnostic beside it so the reason is read rather than remembered.
#
# It is worth being plain about what that costs, since a row moving backwards
# is exactly what this catalogue exists to make impossible to do quietly:
# **the runtime's ISO C unit is no longer portable to a target whose C library
# declares no `_longjmp`.** Every target this compiler admits declares one. A
# port to one that does not gets the conditional back, with a record.
unit  pasrt.c            blocked
unit  pasrt_posix.c      blocked
unit  pasrt_task.c       crt _UCRT
unit  pasrt_unicode.c    compiles

# --- the headers the target has not got -----------------------------------
#
# `pasrt.c` and `pasrt_task.c` have every header they name; what blocks them
# is names inside those headers, which is a different claim and is not this
# file's.
#
# `pasrt.c` **compiles here since ADR-0373**, and getting it there took three
# records. ADR-0370 removed `fmemopen` and `open_memstream`, neither of which
# §6.7.5.5 had ever asked for. ADR-0371 closed the emitter's half of the
# non-local goto: `_setjmp` is an *arity* and not a spelling, `setjmp(x)`
# expanding to `_setjmp(x)` on glibc and `_setjmp((x), frame)` on mingw, and
# the compiler now writes whichever its target wants. ADR-0373 closed the
# runtime's half, which is the jump -- `_longjmp` where POSIX declares one and
# `longjmp` where it does not, the one catalogued conditional in this runtime.
#
# **The name it needed was present in some mingw-w64 builds and not others**,
# which is why the toolchain is pinned above: Ubuntu 24.04's declares
# `_longjmp` and Debian trixie's v14 does not. That difference is now
# irrelevant to whether this unit compiles, which is the better place for it
# to be.
#
# For `pasrt_task.c` it was `timespec_get`/`TIME_UTC`, and measurement settled
# it: both are `#ifdef _UCRT` in mingw's own <time.h>, and the unit compiles
# clean under `-D_UCRT`. **Confirmed against a real UCRT sysroot on
# 2026-09-09** rather than only against the macro: with
# `mingw-w64-ucrt64-dev` installed, `__MSVCRT_VERSION__` is 0xE00, the
# headers define `_UCRT` themselves, and the unit compiles with no `-D` at
# all. The row below is checked with the macro because that needs no sysroot
# and every machine can run it; the sysroot is what says the macro is not a
# fiction. The same sysroot leaves `pasrt.c` blocked on `_longjmp`, so that
# name is not a CRT question either. So it is a CRT selection and not a gap, which is what
# the `crt` row above says and what the gate now proves on every run. Debian's
# packaged toolchain here is msvcrt-based (`-win32` and `-posix` are threading
# variants, both msvcrt), which is why the default compile still fails.
#
# **Seven, and the shape of them is the finding.** `pasrt_posix.c` names ten
# headers that ARE there -- dirent.h, errno.h, fcntl.h, signal.h, stdio.h,
# stdlib.h, string.h, sys/stat.h, time.h, unistd.h -- so the directory walk,
# the file information and the process plumbing are not what is missing. What
# is missing is sockets, the terminal and `posix_spawn`, which is the layer
# doc/roadmap.md says nobody had costed. A first target that ships without
# PasNet is therefore a much smaller thing than "port pasrt_posix.c", and
# this file is how that stays true rather than being re-argued.
header  pasrt_posix.c  netdb.h
header  pasrt_posix.c  poll.h
header  pasrt_posix.c  spawn.h
header  pasrt_posix.c  sys/ioctl.h
header  pasrt_posix.c  sys/socket.h
header  pasrt_posix.c  sys/wait.h
header  pasrt_posix.c  termios.h
