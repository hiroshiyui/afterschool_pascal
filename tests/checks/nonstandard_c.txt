# Every identifier runtime/pasrt.c uses that ISO C does not declare.
#
# runtime/pasrt.c is the runtime proper, and how close it stays to the standard
# decides what a port to another C library costs. Measured on 2026-08-22 it was
# *three names*, and access made a fourth on 2026-08-23; ADR-0370 then removed
# two of them and it is *three* again -- see
# doc/roadmap.md's cross-platform chapter, where this replaced the claim that
# "the file model is a POSIX assumption".
#
# tests/checks/runtime_isoc.py reads this file and fails in both directions: a
# fourth dependency appearing, and one of these three going away while the
# entry stays. Add a name only with the argument for why ISO C could not do it.
#
# **This list can only ever hold functions**, and ADR-0186 is where that turned
# out to be a rule rather than a habit. The list is proved complete by
# stripping the non-ISO includes from a copy and requiring what is left to
# compile: an undeclared *function* is a warning that can be silenced, and an
# incomplete `struct stat` is an error that cannot. So a POSIX dependency
# needing a type could never be catalogued here however well it was argued for,
# and runtime/pasrt_posix.c is where such a thing goes instead. The headers
# that file may include are the second list below, and the gate reads both.
#
# **There is a third translation unit and it appears in neither list.**
# runtime/pasrt_unicode.c (ADR-0190) needs nothing outside ISO C -- no
# allocation, no locale, not even the names excused here -- so the gate holds it
# to a strict compile with no catalogue at all. That is a stronger claim than
# either file above carries, and it is free while it stays true; the day it
# needs a name is the day it takes a section here, with the argument.
#
# Format: the identifier, then a blank-line-separated argument above it.

# ISO 7185 §6.8.2.4 / ISO/IEC 10206:1991 §6.9.2.4's non-local goto. ISO C's setjmp is a macro whose expansion must
# appear in a very restricted set of contexts, and the generated code calls it
# directly -- pas_jump_env hands back the address to call it on, because a
# wrapper would return before the jump could arrive (the frame setjmp saves has
# to be the one longjmp returns into). POSIX's function form is what can be
# named from LLVM IR at all, and it is the single non-`pas_` symbol the emitted
# module declares.
_setjmp
_longjmp

# `fmemopen` and `open_memstream` stood here and are gone (ADR-0370). The
# argument they carried was that ADR-0057's readstr and writestr are "a FILE*
# over memory, which ISO C has no way to make" -- and that first half is true
# while the second was never the requirement. What §6.7.5.5 needs is an
# auxiliary `text` variable backed by memory, not a `FILE *`; the buffer is
# now written into and read out of directly, and the read and write primitives
# branch once on which destination they have. They were two of the three names
# that stopped this translation unit compiling for a target that is not POSIX
# (ADR-0369), and `tmpfile()` -- ISO C, and used then for an internal file --
# was measured at 88 times the cost and refused. **`tmpfile` is not used here
# any more either** (ADR-0388): wasi-libc declares it and does not define it,
# so an internal file is now an exclusive `fopen` and a `remove`, both of
# them ISO C as well. That changes nothing about this list, which never held
# an ISO C name; it is noted because the sentence above would otherwise send
# a reader looking for a call that is gone.

# ISO/IEC 10206:1991 §6.7.5.6's bind: "the binding shall be
# implementation-defined", and this processor's is that the attempt succeeds
# when the name designates something that exists or something whose directory
# does (E.16). ISO C has no way to ask whether a path exists without creating
# it -- fopen for reading says nothing about a file that is unreadable but
# there, and fopen for appending creates what it asks about.
access



# --- the preprocessor conditionals, and there is meant to be almost none ----
#
# No translation unit here held one until ADR-0373, and the discipline that
# made that true is worth keeping: each unit is bounded by what it may depend
# on, and a `#if` makes that bound depend on who is compiling. The set below
# is compared **both ways**, so a second one is a decision with a record
# rather than a habit, and a row whose condition is gone is describing a
# runtime that no longer exists.
#
# Format: `conditional: <unit> <macro>`, with the argument above it.

# **There are none, and that is the finding.** The list below is empty and the
# gate compares it both ways, so this is a claim rather than a silence.
#
# One row stood here for a week. `runtime/pasrt.c` reached the non-local
# goto's jump through `_longjmp` where POSIX declares one and `longjmp` where
# it does not -- mingw-w64 declaring no `_longjmp` at all -- and no portable
# spelling existed in either direction: `longjmp` after `_setjmp` works on
# glibc, whose buffer carries a flag, and breaks on Darwin, where it would
# restore a mask that was never saved (ADR-0373). ADR-0380 dropped the target
# rather than the rule. Every target this compiler admits is POSIX and
# declares `_longjmp`, so the unit names it directly and this list is empty
# again.
#
# What that buys is the sentence a port reads first: **a unit here is bounded
# by what it may depend on, and no `#if` makes that bound depend on who is
# compiling.** Adding one back is a decision with a record.

# --- runtime/pasrt_posix.c: the headers, not the names ----------------------
#
# The second translation unit (ADR-0186) is not held to ISO C, because what
# puts a routine there is needing a POSIX *type*. So what is bounded for it is
# the set of headers it may include -- the right granularity for "what a port
# has to supply", and one a gate can check without conjuring a struct.
#
# Everything in that file is `pasx_`, the prefix a Pascal program binds by name
# (ADR-0131), so a system without these loses library routines and not the
# language. Format below: `header: <name.h>`, with the argument above it.

# ADR-0185: what a file *is*, for PasFS.Info. ISO C reaches none of the three
# answers -- <time.h> knows nothing of files, so a modification time has no
# standard source at all; whether a path is a directory has none either; and a
# size alone could be had from fseek and ftell, but only by *opening* the file,
# which fails for a directory and for anything the caller may not read.
#
# It is in the runtime rather than in lib/dialect/pasfs.pas because of
# ADR-0185's fifth decision: AP 6.7.7.6.2 would let the module declare
# `struct stat` and cross it, and `struct stat` is a different struct on macOS.
# This file is compiled by the C compiler of the machine being built for, which
# is the only place that layout question has a known answer.
header: <sys/stat.h>

# F_OK, for telling "nothing there" from "you may not look" without ENOENT --
# one header already in pasrt.c's own dependency for `access`.
header: <unistd.h>

# ADR-0188: the name of a directory entry, for PasDir. The offset of `d_name`
# is what differs between systems -- glibc puts an `unsigned short` and an
# `unsigned char` in front of it, macOS a 64-bit seek offset and two 16-bit
# fields, and POSIX requires only `d_ino` and `d_name`, in any order. So this
# is ADR-0185's fifth decision again: a module may not declare that struct, and
# the C compiler of the target reads the target's own header.
#
# `opendir` and `closedir` are *not* here and need not be: neither has a struct
# in its signature, so lib/dialect/pasdir.pas binds them itself and owns the
# `DIR *` as a handle (AP 6.4.12). Only the member access needed a header.
header: <dirent.h>

# ADR-0203: a TCP connection, for PasNet. `struct sockaddr` is the reason --
# it is not one struct but a family of them, a program never declares the one
# it is using, and a library may not declare any of them (ADR-0185's fifth
# decision). Everything socket-shaped is behind `pasx_socket_*`.
header: <sys/socket.h>

# ADR-0203: `getaddrinfo` and `getnameinfo`, which is what keeps this list at
# two headers rather than four. Both ends of every call in PasNet are
# *strings* -- a host and a service -- so nothing here names an address
# family, a port number or an address, and <netinet/in.h> and <arpa/inet.h>
# are not needed at all. It is also what gives a caller IPv6 without asking:
# the loop takes the first address that works.
header: <netdb.h>

# ADR-0205: `struct pollfd`, for PasNet.Wait. This is the header that makes a
# server serve more than one client, and it is a *type* dependency rather than
# a name one for the usual reason -- ISO C has no way to ask whether reading a
# descriptor would block, and the array `poll` takes is a struct whose members
# a program would have to declare. `select` would have cost `fd_set`,
# `FD_SETSIZE` and four macros for the same answer.
#
# It buys the readiness of a *descriptor* and nothing else: whether a line is
# already sitting in the runtime's own buffer is the other half of the
# question and is answered above it, in C the compiler can see.
header: <poll.h>

# ADR-0262: `struct termios`, for PasTerm's raw mode. It is the worst subject
# ADR-0185's fifth decision has met so far -- not merely a layout that differs
# between systems, but one whose `c_cc` array is 32 elements on Linux and 20 on
# macOS, and whose flag *bits* differ as well as its offsets. A module carrying
# it would be one platform's header written out as a constant, and every
# `tcsetattr` from it on another system would be a terminal put into a state
# nobody asked for.
#
# ISO C reaches none of this at all: <stdio.h> knows about streams and nothing
# about the device behind one, so whether input is echoed, whether it is
# assembled into lines, and whether a read waits for a newline have no standard
# answer. `isatty` is in <unistd.h> above and needs no type.
header: <termios.h>

# ADR-0262: `TIOCGWINSZ` and `struct winsize`, for the size of the window.
# **POSIX has no window size** -- this is the one entry here naming something
# no standard defines, and it is named rather than argued away because the
# alternatives are worse: the `COLUMNS` environment variable is a shell's
# opinion recorded before the window was last resized, and there is nothing
# else. The request and the struct are BSD-derived and are on every Unix this
# compiler admits a target for.
header: <sys/ioctl.h>

# ADR-0362: `posix_spawn_file_actions_t`, for PasProcess.Execute -- running a
# command as *words* rather than as a line a shell re-reads. The type is what
# puts it here: it is an opaque struct a caller declares by name, it has no
# defined layout at all, and the three routines that fill it in take its
# address. `posix_spawn` rather than `fork` because this language has two
# threads of control (AP 6.9.3.12) and a `fork` in a process with more than one
# leaves the child holding a lock nothing will unlock.
#
# ISO C has one way to run a command, `system`, and it is a *string*: the shell
# decides where the words are, so every value in it is read as syntax. That is
# the defect this entry exists to have closed.
header: <spawn.h>

# ADR-0362: `WIFEXITED` and `WEXITSTATUS`, for what the child did. They are
# macros over a wait status and `waitpid` is declared here beside them, so
# there is no name to catalogue instead -- which is the distinction this
# section exists for. PasProcess.ExitCode decodes `system`'s status by hand
# because `system` is ISO C and its caller is a *module*; here the runtime is
# already reading the status and the macros of the system that wrote it are
# the right reader.
header: <sys/wait.h>

# ADR-0362: `O_WRONLY`, `O_CREAT` and `O_TRUNC`, for the mode of
# PasProcess.ExecuteToFile -- the child's output sent straight to a file. They
# are macros whose *values* differ between systems, which is the same reason
# `struct termios` is here and not a number written out in a module: `O_CREAT`
# is 0100 on Linux and 0x200 on macOS, and a module carrying either would open
# something else on the other.
#
# ISO C's `fopen` cannot be asked for this at all -- what has to be opened is
# descriptor 1 *of another process*, before it runs, and a `FILE *` in this one
# is not that.
header: <fcntl.h>
