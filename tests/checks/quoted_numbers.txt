# What a document quotes from a gate, and which gate answers it (ADR-0379).
#
# Three fields, separated by `|`:
#
#   <document> | <gate> | <pattern>
#
# The pattern is matched against the document; **every number it captures must
# appear in that gate's own summary line** from the last suite run, and the
# pattern must go on matching -- a sentence reworded away from its row is a row
# that has stopped watching, and that is the direction a catalogue rots in.
#
# The gate is named as it names itself at the start of its summary, which is
# the convention every check in this directory follows. `sanitize.py` runs in
# four modes and writes `sanitize[address]:`, so the mode is part of the name.
#
# **What does not belong here**: a number a *record* quotes. An ADR states what
# was true when the decision was taken and is immutable (ADR-0001), so binding
# one to today's answer would be asking history to change. Nor a number that is
# a *floor* written into a gate's source -- that is a constant, and the gate
# reading it is the check.
#
# Add a row when a document states a number some gate reports. The six stale
# numbers of 2026-09-09 were each found by running the gate and by nothing
# else, and writing this catalogue found two more in README that the audit had
# not thought to run: 887 cases where ctest runs 917, and 417 scenarios where
# tests/spec/ holds 427.

# **CLAUDE.md's row was added after the sentence went stale, which is the
# argument for it.** That file's gate table said `pasrt_posix.c` wants seven of
# seventeen headers -- mingw-w64's answer -- for as long as the wasi column
# existed, because the switch edited the catalogue and README and not the table
# a session loads before every change. README's sentence had a row here and was
# right; the one nothing watched was the one that drifted.

# The roadmap's Windows row quoted the same seven and had a row here; ADR-0380
# moved that row to `doc/history.md` whole, and a number a *record* quotes is
# out of scope on purpose -- history says what was found then. README's
# sentence above is the live one.

# **These three rows named `target-layout` first and that was wrong**, which
# CI found on clang 19 and this machine could not: `target-layout` abstains
# for a target whose layout this clang disagrees about, so on trixie and on
# Ubuntu it compares *six* and says six, while the documents correctly say
# seven targets are admitted. The two numbers answer different questions --
# how many exist, and how many could be compared here -- and a row that holds
# one against the other is red on exactly the machines where the abstention is
# working as designed. `setjmp-arity` states `N of 7 admitted target(s)`, and
# the 7 there comes from the compiler's own `--target=` refusal rather than
# from what clang can do, so it is the same question the sentences ask.
# **The lesson is the row's, not the gate's**: choosing what to watch means
# choosing a gate that answers the sentence's question, and a gate that
# abstains honestly is the one most likely to expose a mismatched pairing.

# **The admitted-target count went stale in two documents at once** on
# 2026-09-10 -- `doc/glossary.md` said five and `doc/implementation-defined.md`
# said six, where `--target=` had admitted seven. Neither was watched, and the
# 2026-09-09 audit's finding repeated itself exactly: the register was current
# and the stale things were outside it. `target-layout` reads the list from the
# compiler's own refusal and prints how many it compared, so these three rows
# are that number held against the three live sentences that quote it. A record
# quoting it stays out of scope -- an ADR says what was true then.
