# Cases that do not pass for wasm32-wasi (ADR-0385).
#
# **519 of 598 corpus programs compile for WebAssembly, link against the two
# runtime units that build for it, and answer their golden under a WASI
# runtime.** These are the rest, and the gate beside this file fails in both
# directions: a case that starts failing is a regression, and a case that
# stops failing is progress somebody has to record.
#
# It is a long file and every row is one of six causes. That is the point --
# **this is a port's work queue and not a list of defects**. Nothing here is
# the compiler getting an answer wrong; the two behavioural differences that
# were, a stack overrun and a lost `SOURCE_DATE_EPOCH`, are fixed and the
# fixes are in `tools/pascalcc` and in the runner command.

# --- 52 cases: `tmpfile` -----------------------------------------------
#
# **The single largest thing between this corpus and WebAssembly, and it is
# one function.** wasi-libc *declares* `tmpfile` and does not define it --
# `runtime-nonposix` records the deprecation warning and this is where that
# warning becomes a link error. It is 6.7.5.5's auxiliary file: `rewrite(f)`
# on a file variable bound to no name, which is what a program writes when it
# wants scratch storage, and what this compiler's own scratch files use.
#
# A port closes all 52 with one routine: a temporary file opened in a
# directory the module was granted, named by the runtime rather than by the C
# library. Nothing in the language or the emitter is involved.

# --- 2 cases: a foreign name this target has not got ---------------------------
#
# Not a link error: wasm-ld leaves an unresolved function as an *undefined
# weak* symbol, so the module links and traps on `unreachable` the first time
# the call is reached. Both of these bind a C routine by name for the sake of
# testing the boundary itself, and the name is not in wasi's libc. The trap is
# the right outcome and the case is not portable, which is what this row says.
tests/dialect/foreign_int64_handle.pas
tests/dialect/foreign_slice.pas

# --- 1 cases: the non-local goto, and the runtime running it -------------------
#
# **The compiler emits this correctly and the runner cannot run it.** A
# `goto` out of a procedure lowers through LLVM's SjLj on this target, which
# emits a wasm *tag* -- the exception-handling proposal -- and wazero answers
# `tag section not supported as feature "exception-handling" is disabled`. A
# runtime that implements the proposal runs it; that is a fact about which
# `.wasm` engine is installed, and the gate names the one it used in its
# summary line so a reader can tell this row from a defect.
tests/goto_nonlocal.pas
