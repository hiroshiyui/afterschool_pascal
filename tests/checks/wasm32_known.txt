# Cases that do not pass for wasm32-wasi (ADR-0385).
#
# **558 of 598 corpus programs compile for WebAssembly, link against the two
# runtime units that build for it, and answer their golden under a WASI
# runtime.** These are the rest, and the gate beside this file fails in both
# directions: a case that starts failing is a regression, and a case that
# stops failing is progress somebody has to record.
#
# It was 519, and the 52 that moved were one function. `tmpfile` is ISO C,
# wasi-libc declares it and does not define it, and `runtime/pasrt.c` called
# it for §6.7.5.5's auxiliary file -- so the whole unit linked with an
# undefined symbol. ADR-0390 stopped calling it: an exclusive `fopen` and a
# `remove` are both ISO C and are the whole of what `tmpfile` was doing, so
# the fix cost no preprocessor conditional and applies on every target.
# **Thirteen of the 52 were behind a second cause as well** and have moved to
# the row that names it, which is the half of this exercise a summary number
# hides.
#
# It is a long file and every row is one of six causes. That is the point --
# **this is a port's work queue and not a list of defects**. Nothing here is
# the compiler getting an answer wrong; the two behavioural differences that
# were, a stack overrun and a lost `SOURCE_DATE_EPOCH`, are fixed and the
# fixes are in `tools/pascalcc` and in the runner command.

# --- 16 cases: processes, sockets, directories and the terminal -----------------
#
# `runtime/pasrt_posix.c` wants five headers wasi has not got, so none of it
# is built and every `pasx_` routine is undefined. What each program here
# wants is named by the symbol the link reports: a process, a socket, a
# directory walk, `isatty`. This is the part of a port with a decision in it
# -- wasi has its own socket interface and no processes at all -- and
# ADR-0382 sets out the shape.
#
# **An absent `pasx_` shows up in three ways and all three are here**, which
# is worth knowing before reading a failure as a defect. `lib_fs` and
# `lib_dir` stop at the *link* with `pasx_file_info` named. `lib_io` and
# `lib_os` link -- wasm-ld having left the symbol undefined weak -- print
# their first few lines and then trap on `unreachable` at the call. And
# `lib_path` neither fails nor traps: `PasPath` reports the refusal its own
# way, so the program answers `symlink made = no` and differs from its golden
# by two lines. The third is the shape to watch for, because it is a *wrong
# answer* and nothing about it says wasm.

# --- 4 cases: the non-local goto, and the runtime running it -------------------
#
# **The compiler emits this correctly and the runner cannot run it.** A
# `goto` out of a procedure lowers through LLVM's SjLj on this target, which
# emits a wasm *tag* -- the exception-handling proposal -- and neither engine
# tried here implements it: wasmedge refuses the module with `illegal opcode,
# Code: 0x117` before a single instruction runs, and wazero answers `tag
# section not supported as feature "exception-handling" is disabled`. An
# engine that implements the proposal runs it; that is a fact about which
# `.wasm` engine is installed, and the gate names the one it used in its
# summary line so a reader can tell this row from a defect.
#
# Three of these four arrived from the `tmpfile` row and are the reason that
# row could not be closed by counting. They are not *about* the non-local
# goto -- `defer.pas` and `handle.pas` are about a deferred statement and a
# handle -- but each contains a jump out of a procedure somewhere, and one
# `@_setjmp` in a module is enough for the whole module to be refused. Asked
# of the emitted IR rather than of the source: `pascalc --target=wasm32-wasi
# tests/dialect/defer.pas` writes two calls to `@_setjmp`.
tests/dialect/defer.pas
tests/dialect/handle.pas
tests/goto_files.pas
tests/goto_nonlocal.pas

# --- 3 cases: a foreign name this target has not got ---------------------------
#
# Not always a link error: wasm-ld may leave an unresolved function as an
# *undefined weak* symbol, so the module links and traps on `unreachable` the
# first time the call is reached. All three of these bind a C routine by name
# for the sake of testing the boundary itself, and the name is not in wasi's
# libc. The trap is the right outcome and the case is not portable, which is
# what this row says.
#
# `handle_bare_call.pas` is the one with the joke in it: the parameterless C
# routine it binds to exercise AP 6.7.7.6's bare call is `tmpfile`. ADR-0390
# took `tmpfile` out of the *runtime* and cannot take it out of a program
# that asks for it by name, which is exactly the line that decision draws.
tests/dialect/foreign_int64_handle.pas
tests/dialect/foreign_slice.pas
tests/dialect/handle_bare_call.pas

# `tests/dialect/owned.pas` and `tests/dialect/take.pas` stood here for a day
# as *a relative path, in a module granted only `/`*, and **the row was about
# the engine's version and not about the port**. Both open a scratch file
# beside themselves by a bare name; under wasmedge **0.16** that answers a
# null handle with `--dir /:/`, and under **0.17** it answers a stream. CI
# installs testing's 0.17.1 and the two have passed there from the first run.
#
# The row proposed its own fix -- a runner granting the case's working
# directory -- and that was measured here and is **wrong**: adding a preopen
# named `.` makes a *relative* path resolve and an **absolute** one stop,
# which is 27 corpus cases traded for these 2, and reversing the order
# reverses which half works. On 0.16 this engine serves absolute paths or
# relative ones and not both, so there is nothing `wasi_run.py` can arrange.
#
# **It was CI that made this findable**, in the direction a catalogue is least
# expected to fail: the two passed there and failed here, so the gate reported
# *progress* and refused to let it go unrecorded. A row true on one machine
# and false on another is a row about the machine -- so the rows are gone and
# `wasm32.py` now probes the engine instead, and abstains where it is too old
# rather than reporting two defects that are not there.
